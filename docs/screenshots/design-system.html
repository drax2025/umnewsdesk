01 — Overview
Chronicle Editorial Ops System

A compact, high-trust design language for internal editorial staff — reporters, editors, sub-editors, and legal reviewers who operate this interface for 6–8 hours a day. Optimised for information density, status clarity, and long-session legibility. Not a public product. Not a startup template.

02 — Color
Restrained neutral system — one accent

The palette operates in two modes. All surfaces, borders, and text are neutral. The single accent (blue) appears only for interactive semantics: active nav state, selected items, primary CTAs. Status colours (success / warn / danger) appear only in badge contexts, never as page-level treatments.

03 — Typography
Inter — compact, legible, system-native

One type family: Inter. No display serif, no decorative faces. Mono (SF Mono / Cascadia Code) is reserved for IDs, timestamps, word counts, and column headers — not for prose. Type caps at 15px for headlines within the app shell; no oversized hero text in operational screens.

04 — Spacing
4px grid — no arbitrary values

07 — Layout
Shell, split panels, semantic memory

Every screen inherits the same shell: 216px left sidebar, 48px topbar, and a flex-1 main area. The main area adapts: full-width table, split queue+detail, or 3-column (queue + detail + semantic sidebar). Never break the sidebar or topbar per screen.

08 — Motion
State-revealing only — no ambient animation

Motion communicates state change. Every transition either confirms an action (row appearing, modal fading in) or reveals information (SLA countdown ticking). Hover to test each demo.

Tokens (hover each to demo)
Micro — 100ms ease
Row hover, icon opacity
Fast — 150ms ease-out
Button press, badge swap
Standard — 220ms ease-in-out
Panel open, card select
Modal — 260ms ease-out
Confirmation dialog

Respect prefers-reduced-motion: set all durations to 0ms. SLA countdowns continue updating text content regardless.

09 — Accessibility
WCAG 2.1 AA minimum — keyboard-first

All status information must be conveyed by text or shape, not colour alone. Risk badges use text (HIGH / MED / LOW). Stage pills use a dot + label. SLA urgency uses colour + timestamp. Every interactive element is reachable by keyboard and shows a visible focus ring.

Focus ring — Tab to test each

3px box-shadow ring using color-mix(in oklab, var(--accent), transparent 55%). Never remove :focus-visible.

10 — Anti-patterns
Explicit prohibitions for this product

These failures are common in AI-generated dashboards and startup SaaS templates. Every one has been explicitly rejected for Union Media's editorial ops system.

Do
One accent colour used only for interactive semantics
Stage status via dot + text label in a pill
Left sidebar nav with icon + label on every item
Compact sans-serif at 13px for all UI text
Row hover via background tint — no border change
Mono font for IDs, timestamps, and counts
Dark-first with fully specified light mode tokens
Dense but breathable — 8–16px consistent padding
Motion only on state change, 100–220ms max
Confirm-with-rationale for all destructive actions
Don't
Purple / indigo AI gradients as backgrounds or cards
Coloured left border on cards as a state indicator
Icon-only sidebar navigation without visible labels
Oversized hero headings (24px+) in operational screens
3-card "feature" marketing layouts inside the app
Floating decorative blobs or gradient orb backgrounds
Emoji as navigation or status icons
Invented metrics or placeholder stat cards
Circular progress rings for loading / SLA state
Multiple competing accent colours per screen
